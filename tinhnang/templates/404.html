cong_cu.py - Core Modules

class chay_terminal

Mục đích: Quản lý tiến trình con bất đồng bộ, đảm bảo mỗi lần chỉ một lệnh active, tránh xung đột.

📋 Phương thức:

run_cmd(command, **kwargs) - Chạy lệnh shell, không block, trả về dict trạng thái
dang_chay() - Đọc stdout từ tiến trình đang chạy, trả về khi kết thúc
dang_thuc_su_chay() - Kiểm tra tiến trình còn sống không
dung_terminal() - Dừng tiến trình (SIGINT/killpg)

🔧 Cơ chế: Dùng subprocess.Popen với preexec_fn=os.setsid để tạo process group, hỗ trợ kill toàn bộ tiến trình con.

class WifiManager

Mục đích: Điều khiển card WiFi, quét mạng, kết nối, auto connect thông minh.

📋 Thuộc tính:

  • interface - Giao diện mạng (mặc định "wlan0")
  • original_mac - MAC gốc để khôi phục
  • target_ssid - SSID đang cố kết nối

📋 Phương thức chính:

scan() - Quét WiFi, trả về list {ssid, bssid, rssi, quality, security, is_wps, vendor, band}
connect(ssid, password, security) - Kết nối WiFi, xác minh SSID thực tế
connect_auto(result_data, ten, auto_change_mac) - Auto connect từ database, tối ưu thứ tự mật khẩu
change_mac(new_mac) - Đổi địa chỉ MAC ngẫu nhiên
set_status(mode) - Bật/tắt WiFi (svc wifi enable/disable)
restart() - Khởi động lại card WiFi

🔍 Auto Connect chi tiết:

1. Tìm SSID trong database → dùng mật khẩu đó.
2. Nếu không, lấy danh sách password UNIQUE từ database.
3. Sắp xếp theo tần suất xuất hiện (phổ biến nhất trước).
4. Thử từng password, chỉ thử mỗi pass 1 lần.
5. Nếu thất bại và auto_change_mac=True → đổi MAC, thử lại tối đa 3 lần.

class FileManager

Mục đích: Đọc/ghi file với mã hóa XOR, kiểm tra toàn vẹn bằng SHA256, định dạng ACDV độc quyền.

📋 Cấu trúc file ACDV:

┌──────────────┬──────────┬────────────┬──────────┬─────────────────┐
│ Fingerprint │ Header │ Hash │ Data │ Magic End │
│ (3 bytes) │ Len(2) + │ (64 bytes)│(encrypted)│ (2 bytes) │
│ 0xAC 0x44 0x56│ JSON │ SHA256 │ XOR 0x69 │ 0x55 0xAA │
└──────────────┴──────────┴────────────┴──────────┴─────────────────┘

📋 Phương thức:

save_file(filename, content, data_type, who_am_i) - Lưu file với mã hóa và chữ ký
read_file(filename) - Đọc file, giải mã, xác thực hash
sync_and_upgrade_database(filename) - Nâng cấp DB lên version mới (thêm password_id)
get_unique_passwords(filename) - Lấy danh sách password UNIQUE
get_password_by_id(filename, password_id) - Lấy thông tin password theo ID
class NetworkScanner

Mục đích: Quét mạng LAN đa vòng, phát hiện thiết bị, quét cổng, dự đoán OS, cache RAM + lọc trùng lặp.

📋 Phương thức:

scan_network(ports, fast_mode, scan_rounds, reset_cache) - Quét toàn bộ mạng LAN (mặc định 3 vòng)
scan_network_nmap(mode) - Quét LAN bằng nmap (fast/normal/thorough/stealth)
quick_scan() - Quét nhanh chỉ HTTP/HTTPS (2 vòng)
scan_specific_host(target_ip, ports, port_timeout) - Quét một host cụ thể
_merge_host_into_cache(ip, data) - Gộp dữ liệu host vào cache, union ports
get_cache() / clear_cache() - Lấy/xóa cache RAM

⚡ Tối ưu hóa:

- Cache RAM static: Lưu kết quả giữa các vòng quét, tránh quét lại host đã biết.
- Nhiều vòng quét: Tăng độ phủ, phát hiện host chậm phản hồi.
- Merge port: Nếu host được phát hiện lại, union cổng mở + đếm hits.
- Song song hóa: Ping 30 host và quét 15 cổng cùng lúc.
- ⭐ v3.4: Emit progress % qua emit_progress().

pws.py - WPS Attack Engine

class WPSpin

Mục đích: Tạo PIN WPS dựa trên MAC address (hỗ trợ 20+ algorithm).

📋 Các loại algorithm:

ALGO_MAC - PIN dựa trên MAC (24-bit, 28-bit, 32-bit, D-Link, ASUS)
ALGO_EMPTY - PIN rỗng
ALGO_STATIC - PIN tĩnh (Cisco, Broadcom, Realtek, Edimax, Thomson...)

📋 Phương thức:

generate(algo, mac) - Tạo PIN 8 số từ algorithm và MAC
getSuggested(mac) - Lấy PIN gợi ý dựa trên OUI
checksum(pin) - Tính checksum chuẩn WPS
class Companion

Mục đích: Main WPS attack engine, điều khiển wpa_supplicant, thu thập dữ liệu Pixie Dust.

📋 Quy trình tấn công:

1. Khởi động wpa_supplicant -K -d (log keys)
2. Gửi WPS_REG bssid pin → wpa_supplicant
3. Thu thập PKE, PKR, E-Hash1, E-Hash2, AuthKey, E-Nonce
4. Chạy pixiewps --pke ... --pkr ... --e-hash1 ... --e-hash2 ...
5. Nếu tìm được PIN → thử lại với PIN đó
6. Thành công → lấy WPA PSK từ "Network Key"

Mục đích: Xử lý logic chính, khởi tạo WifiManager, NetworkScanner, FileManager.

📋 Trạng thái flags:

class WebSocketServer

Mục đích: WebSocket server real-time, xử lý command từ client.

📋 Cơ chế Stop task:

Khi nhận lệnh "stop" hoặc "stop_task":
→ pkill -9 wpa_supplicant, pixiewps, iw, ping, nc
→ rm -rf /data/local/tmp/wpa_ctrl_*
→ svc wifi disable/enable (khôi phục WiFi)
→ Reset flags (is_processing = false)
→ Server vẫn chạy, có thể tiếp tục thao tác

📋 Các command handler:

_handle_scan_async() - Quét WiFi
_handle_lan_scan_async() - Quét LAN đa vòng
_handle_connect_with_password_async() - Kết nối với mật khẩu
_handle_wps_attack_async() - Tấn công WPS
_handle_auto_connect_async() - Auto connect từ database
_handle_dirb_async() - Quét thư mục ẩn (Dirb)
_handle_shutdown_async() - Tắt tool hoàn toàn
_stop_current_task_immediately() - Dừng task ngay lập tức
_handle_client_disconnect() - ⭐ v3.4: Xử lý WS mất kết nối giữa task
_check_and_reset_stale_session() - ⭐ v3.4: Auto-reset session cũ khi start

🛡️ Cơ chế Module Blocking (v3.4):

WS disconnect giữa task:
→ cleanup_orphan_processes() (kill hết process rác)
→ module_hang_counts[module]++
→ Nếu >= max_hangs (3): blocked_modules.add(module)
→ Client nhận blocked_modules → block nút module
→ Restart tool hoặc reset_blocks để mở khóa

self.resource.load(default_config) - Nạp JSON config, tự sinh nếu chưa có

📋 Class attributes:

category / category_label / category_icon - Menu nav
